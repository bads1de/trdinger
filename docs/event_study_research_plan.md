## 2. 検証データ

- 対象: BTC/USDT:USDT, ETH/USDT:USDT (Bybit永久契約)
- FR: 8h粒度 2020-10〜 / OI: 5min粒度 2020-08(ETH 2020-10)〜 / LSR: 15m〜1d / OHLCV: 多TF
- ⚠️ 全てBybit単一ソース。OIの報告遅延リスクあり→事前に健全性チェック(§4)

## 3. 事前登録仮説(パラメータ凍結)

共通プロトコル:
- 基準分布: 各シンボル・全期間の「全時間」フォワードリターン分布と比較
- フォワード窓: 8h / 24h / 72h / 168h の4種のみ
- コスト: 片道0.04%(taker)+スプレッド考慮せず(保守性注記)
- **全セルを報告する**(都合の悪いセルの省略禁止)
- 発見用/確認用分割: BTC 2020-2023を発見、BTC 2024-2026+ETH全体を確認に使う。
  判定は**確認サンプルのみ**で行う(発見サンプルは設計参考)

| ID | メカニズム | イベント定義(凍結) | 予測 |
|---|---|---|---|
| H1-FR極端負 | ショート過密→スクイーズ燃料 | 直近90日のFR分布で下位2%(かつFR<−0.05%)の8h決算 | ロング優位(フォワードリターン>基準) |
| H2-FR極端正 | ロング過密→長押しリスク | 同上位2%(かつFR>+0.05%) | ショート優位/ロング回避 |
| H3-OIフラッシュ | 清算完了直後の過剰反応 | 24h以内にOIが−15%超減(直近90日で最大級) | 反発(ロング優位) |
| H4-LSR極端 | クラウド側の清算燃料 | LSR(アカウント型)の30日rollingパーセンタイル下位5%/上位5% | 下位=ロング優位/上位=ロング不利 |
| H5-コンフルエンス | 文献一致条件 | H1またはH4下位 かつ OI上昇中(24h変化>0) | 単独より強いロング優位 |

判定基準(各H): 確認サンプルでのフォワードリターン中央値が基準分布中央値を上回り、
勝率≥52%、かつイベント数n≥100。複数窓は代表窓(24h)を主判定、他は参考。

## 4. 実施前のデータ健全性チェック(必須)

1. FR系列: 8h間隔の欠落率、異常値(±1%超)の確認
2. OI系列: 既知カスケード日(2024-08-05, 2025-10-10等)での急落が再現されるか
   (再現しない場合、Bybit OI報告問題の影響とみなしH3は中止)
3. LSR: アカウント型かポジション型かの属性確認、欠落パターン

## 5. 実装物(予定)

- `scripts/event_study.py`: 上記H1-H5を凍結パラメータで実行、全セル出力
- 出力: イベント数/フォワードリターン分布/基準比/勝率 をH×窓×シンボル行列で
- 結果は `results/event_study_results.jsonl` に保存

## 6. 解釈のルール

- 確認サンプルで基準未達のHは「不支持」として記録し、パラメータ微調整での再試行をしない
- 支持された場合も、まず取引コスト感度(片道0.04%→0.1%)で頑健性確認してから次へ
